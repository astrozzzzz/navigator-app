# Navigator — карта, локальная БД, геолокация и уведомления

Мобильное приложение на React Native + Expo (Expo Router, TypeScript). Позволяет
отмечать точки на карте долгим нажатием, прикреплять к каждой метке набор
изображений из галереи устройства и хранит все данные локально в SQLite
(`expo-sqlite`), так что метки и изображения переживают перезапуск приложения.
Приложение также отслеживает текущее местоположение пользователя на карте и
показывает локальное уведомление при приближении к сохранённой метке.

## Установка и запуск

```bash
npm install
npx expo run:android   # development build для Android (эмулятор или устройство)
npx expo run:ios       # development build для iOS (нужен macOS и Xcode)
```

Приложение запускается как **development build**, а не в Expo Go: на Android
`expo-notifications` не работает в Expo Go (см. раздел «Уведомления»), а
карте Google нужен собственный API-ключ.

- **Android**: карта использует Google Maps, нужен API-ключ (Maps SDK for
  Android). В репозитории ключа нет: `app.config.ts` берёт его из переменной
  окружения `GOOGLE_MAPS_API_KEY`. Локально создайте в корне проекта файл
  `.env.local` (он в `.gitignore`):

  ```
  GOOGLE_MAPS_API_KEY=ваш_ключ
  ```

  Без ключа Expo CLI выводит предупреждение, а карта на Android не
  загрузится. Ключ всё равно попадает в собранный APK, поэтому его стоит
  ограничить в Google Cloud Console: только Android-приложение
  `com.anonymous.navigator` и только Maps SDK for Android.
- **iOS**: используется Apple Maps (провайдер по умолчанию), ключ не нужен.

Папки `android/` и `ios/` генерируются из `app.json` (Continuous Native
Generation) и не хранятся в репозитории. После изменения `app.json` или
иконок их нужно пересоздать: `npx expo prebuild --clean`.

## Реализованный функционал

- Полноэкранная карта (`app/index.tsx`) на базе `react-native-maps`.
- Добавление меток долгим нажатием на карту — сразу сохраняется в SQLite.
- Список всех меток с количеством изображений, раскрываемый кнопкой над картой.
- Экран деталей метки (`app/marker/[id].tsx`) с координатами, датой создания,
  галереей прикреплённых изображений, добавлением/удалением изображений и
  удалением самой метки (каскадно удаляет её изображения).
- Выбор изображений из галереи через `expo-image-picker` с запросом
  разрешений и обработкой отказа.
- Файловая маршрутизация Expo Router (`app/_layout.tsx`, `app/index.tsx`,
  `app/marker/[id].tsx`).
- Локальная база данных SQLite через `expo-sqlite` с версионируемыми
  миграциями и React Context для доступа к данным (`contexts/DatabaseContext.tsx`).
- Отслеживание текущего местоположения пользователя в реальном времени
  (`expo-location`) с отображением на карте (`showsUserLocation`) и
  автоцентрированием при первом получении координат.
- Локальные уведомления о приближении к сохранённым меткам (`expo-notifications`,
  радиус 100 м) без дублирования и с автоматической очисткой при выходе из
  зоны или удалении метки.

## Схема базы данных

```sql
CREATE TABLE markers (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    latitude REAL NOT NULL,
    longitude REAL NOT NULL,
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP
);

CREATE TABLE marker_images (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    marker_id INTEGER NOT NULL,
    uri TEXT NOT NULL,
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
    FOREIGN KEY (marker_id) REFERENCES markers (id) ON DELETE CASCADE
);

CREATE INDEX idx_marker_images_marker_id ON marker_images (marker_id);
```

`PRAGMA foreign_keys = ON` включается при каждом открытии соединения, поэтому
удаление маркера каскадно удаляет связанные с ним изображения на уровне БД.
Версия схемы отслеживается через `PRAGMA user_version`; миграции лежат в
`database/migrations/` и применяются по порядку в `database/schema.ts`
(`openDatabase()`), так что при добавлении новой миграции достаточно
создать `00N_*.ts` файл и добавить его в `database/migrations/index.ts`.

## Слой доступа к данным

- `database/schema.ts` — открытие соединения, `PRAGMA`, применение миграций.
- `database/migrations/` — версионированные SQL-миграции (`001_initial.ts`).
- `database/operations.ts` — чистые функции CRUD (`createMarker`,
  `deleteMarker`, `getMarkers`, `getMarkerById`, `addImage`, `deleteImage`,
  `getMarkerImages`), не зависящие от React — каждая оборачивает ошибки SQLite
  в понятные сообщения.
- `contexts/DatabaseContext.tsx` — инициализирует БД при монтировании
  (`isLoading`/`error`), предоставляет CRUD-методы компонентам, держит кэш
  списка маркеров и обновляет его после каждой мутации, закрывает соединение
  при размонтировании провайдера.

## Обработка ошибок

- **Инициализация БД**: `openDatabase()` оборачивает ошибки открытия
  соединения и миграций в описательные `Error`. Если инициализация не
  удалась, `DatabaseProvider` выставляет `error`, экран карты показывает
  сообщение и кнопку «Повторить» (`retry()` закрывает неудачное соединение и
  открывает базу заново).
- **Ошибки отдельных операций** не попадают в общий `error` контекста и не
  блокируют приложение: метод контекста логирует ошибку и пробрасывает её
  вызывающему экрану, который показывает понятное сообщение. Экран метки при
  ошибке загрузки данных предлагает «Повторить» или вернуться к карте.
- **Транзакции**: `deleteMarker` выполняется в `db.withTransactionAsync`,
  явно удаляя изображения маркера и сам маркер одним атомарным блоком (плюс
  подстраховка через `ON DELETE CASCADE` на уровне схемы); если маркер не
  найден (`changes === 0`), выбрасывается ошибка и транзакция не коммитится.
- **Нарушения ограничений / отсутствующие записи**: `deleteImage` проверяет
  `result.changes` и сообщает, если запись не найдена.
- **Уровень UI**: каждый экран отдельно ловит ошибки конкретной операции
  (добавление метки, выбор изображения, удаление) и показывает пользователю
  понятное сообщение, не роняя приложение.
- **Загрузка карты**: пока карта не сообщила о готовности (`onMapReady`),
  поверх неё показывается индикатор загрузки. Если за 15 секунд карта так и
  не загрузилась (нет сети, неверный ключ Google Maps, нет Google Play
  Services), показывается сообщение и кнопка «Повторить», которая
  пересоздаёт `MapView`.
- **Логирование**: в дев-режиме (`__DEV__`) каждая мутация БД логируется в
  консоль (`[database] addMarker …` и т.д.) через `logOperation` в
  `DatabaseContext.tsx`.

## Геолокация

- `services/location.ts` — `requestLocationPermissions()` проверяет, включены
  ли службы геолокации (`hasServicesEnabledAsync`) и запрашивает разрешение
  `requestForegroundPermissionsAsync`; `startLocationUpdates()` подписывается
  на `Location.watchPositionAsync` (точность `High`, интервал 5 с / 5 м) и
  возвращает подписку; `calculateDistance()` — формула Хаверсина, расстояние
  в метрах.
- Точность `High`, а не `Balanced` из примера в задании: с `Balanced` Android
  берёт координаты из сетевой геолокации (Wi‑Fi, вышки), которой нет в
  эмуляторе, и обновления не приходят вовсе. `High` использует GPS.
- Перед подпиской `startLocationUpdates()` сразу отдаёт последнюю известную
  позицию (`getLastKnownPositionAsync`), чтобы карта не ждала первого фикса.
- `app/index.tsx` в `useEffect` запрашивает разрешение, подписывается на
  обновления координат и отписывается (`subscription.remove()`) при
  размонтировании экрана.
- Текущее местоположение передаётся в `components/Map.tsx`, который включает
  `showsUserLocation` и один раз автоцентрирует карту на пользователе
  (`animateToRegion`) при получении первых координат.
- Ошибка (отказ в разрешении, отключённые службы геолокации, а также сбой
  геолокации уже во время работы — через `errorHandler` у
  `watchPositionAsync`) не блокирует использование карты — под картой
  появляется предупреждающий баннер; он исчезает, как только снова приходят
  координаты.

## Уведомления о приближении к меткам

- `services/notifications.ts` содержит `NotificationManager` — хранит
  активные уведомления в памяти (`Map<markerId, ActiveNotification>`).
- На каждое обновление координат `app/index.tsx` вычисляет расстояние до
  каждой метки через `calculateDistance` и сравнивает с
  `PROXIMITY_THRESHOLD_METERS = 100`:
    - если метка в радиусе и уведомления для неё ещё нет — `showNotification`
      сразу показывает его через `Notifications.scheduleNotificationAsync`
      (без даты и интервала; на Android — в канале `proximity` «Приближение к
      меткам») и сохраняет `notificationId` в реестре, чтобы повторные
      срабатывания в радиусе не создавали дубликаты. Пока уведомление
      отправляется, id метки лежит в `pendingMarkerIds` — это защищает от
      дубликата, если проверка сработала дважды подряд;
    - метки вне радиуса передаются в `pruneExcept(nearbyIds)`, который убирает
      уведомление из шторки (`dismissNotificationAsync`) и удаляет его из
      реестра — так уведомление снимается, как только пользователь выходит из
      зоны метки. (`cancelScheduledNotificationAsync` для этого не подходит:
      он отменяет только ещё не показанные уведомления.)
  - Отдельный `useEffect`, реагирующий на изменение списка меток из БД,
    повторяет проверку по последним известным координатам: метка, поставленная
    рядом с пользователем, сразу даёт уведомление, а уведомление удалённой
    метки снимается.
- Разрешение на уведомления запрашивается один раз при монтировании экрана
  карты (`requestNotificationPermissions`), обработчик показа настраивается
  через `configureNotificationHandler` (иначе уведомления не показываются,
  пока приложение активно). Отказ в разрешении не ломает карту — выводится
  баннер с ошибкой, GPS-трекинг продолжает работать.

## Тестирование

### Геолокация

1. Запустите приложение в симуляторе iOS или эмуляторе Android — при первом
   старте появится системный запрос разрешения на геолокацию.
2. Задайте тестовые координаты через симулятор GPS (в iOS Simulator —
   Features → Location → Custom Location…; в Android Studio Emulator —
   Extended controls → Location) рядом с одной из сохранённых меток. В
   эмуляторе Android координаты также можно задать из терминала (сначала
   долгота, затем широта): `adb emu geo fix 37.6176 55.7558`.
3. Проверьте, что синяя точка на карте следует за симулируемым перемещением
   и карта центрируется на пользователе при первом обновлении.
4. Отключите разрешение на геолокацию в настройках устройства и перезапустите
   приложение — под картой должен появиться баннер с ошибкой, карта при этом
   остаётся работоспособной (добавление меток и т.д.).

### Уведомления

1. Создайте метку рядом с текущими тестовыми координатами (в радиусе 100 м).
2. Переместите симулируемые координаты внутрь радиуса — должно появиться
   уведомление «Вы рядом с меткой!»; при повторных обновлениях координат
   внутри радиуса уведомление не должно дублироваться.
3. Переместите координаты за пределы радиуса — уведомление должно исчезнуть
   из шторки; повторный вход в радиус снова покажет уведомление.
4. Проверьте поведение с несколькими метками одновременно (несколько меток
   в радиусе → несколько независимых уведомлений).
5. Удалите метку, находясь рядом с ней — её уведомление должно быть отменено
   отдельным эффектом, реагирующим на изменение списка меток.
6. Сверните приложение (фон) и разверните обратно — `watchPositionAsync`
   переустанавливает обновления через `useEffect` при повторном монтировании
   экрана; фоновое отслеживание не реализовано, см. раздел «Известные
   ограничения».

> **Android + Expo Go**: сам модуль `expo-notifications` бросает исключение
> при импорте на Android внутри Expo Go начиная с SDK 53 (ограничение самого
> пакета, не связано с логикой приложения). `services/notifications.ts`
> подключает модуль лениво и проверяет среду выполнения
> (`Platform.OS === 'android' && isRunningInExpoGo()`), поэтому приложение не
> падает — просто показывает баннер «уведомления недоступны» и продолжает
> отслеживать местоположение. Чтобы проверить реальные уведомления на
> Android, соберите development build (`npx expo run:android` или EAS
> Build) — на iOS Expo Go и в development build на Android уведомления
> работают без ограничений.

## Известные ограничения

- ORM не использовался — выбран прямой SQL через `expo-sqlite` (async API
  `runAsync`/`getAllAsync`/`getFirstAsync`), так как схема простая (две
  таблицы с одной связью) и не требует абстракции ORM уровня Prisma/Drizzle.
- Приложение проверено в эмуляторе Android (development build); на
  реальном устройстве и на iOS не проверялось.
- **«Призрачные» метки на Android.** В `react-native-maps` (проверено на
  1.27.2, New Architecture) нативная карта, скрытая под другим экраном,
  отсоединяется от окна и теряет синхронизацию со списком маркеров: метка,
  удалённая на экране деталей, оставалась на карте. Обход в
  `components/Map.tsx`: пока карта не в фокусе, маркеры не обновляются, а если
  при возврате набор меток изменился — `MapView` пересоздаётся на прежней
  позиции камеры. Кроме того, маркеры передаются карте в порядке создания:
  при вставке в начало списка библиотека на Android затирает соседний маркер
  (issue react-native-maps#5977). Побочный эффект — после удаления или
  добавления метки на экране деталей камера при возврате может немного
  сместиться.
- Изображения хранятся по `uri` из системной галереи (без копирования файла
  в песочницу приложения), поэтому если исходный файл будет удалён из
  галереи, превью в приложении перестанет отображаться.
- Отслеживание местоположения и проверка приближения работают, только пока
  приложение активно на переднем плане (`watchPositionAsync` без фонового
  режима и без `expo-task-manager`); при сворачивании приложения на
  длительное время обновления и уведомления приостанавливаются.
- Реестр активных уведомлений (`NotificationManager`) хранится в памяти
  JS-процесса и не переживает полный перезапуск приложения — при перезапуске
  уведомления для меток в радиусе будут показаны заново при следующем
  обновлении координат, что является ожидаемым поведением для этой реализации.
- На Android в Expo Go (SDK 53+) модуль `expo-notifications` недоступен
  совсем, поэтому уведомления проверяются только в development build (на iOS
  локальные уведомления работают и в Expo Go).
- Порог приближения (`PROXIMITY_THRESHOLD_METERS = 100`) захардкожен в
  `app/index.tsx`; для продакшена его стоит вынести в настройки пользователя.
